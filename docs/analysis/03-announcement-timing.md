# 3. When to announce

## Decision context
KPM announces weekday status at about **5:45 PM** (to let hostel students travel). The question this project answers with data: *given the afternoon and evening trend, what is the best time to announce?*

### Three usual scenarios
| Scenario | Pattern | Action |
|---|---|---|
| **Best - improving** | API < 100 and falling | announce open early |
| **Base - unstable** | API 101-180, flat or rising | open with restrictions / PdPR ready, re-check at 8 PM |
| **Worst - deteriorating** | API > 180, or > 150 for 3 days | close / PdPR immediately; do not wait for the scheduled time |

Suggested protocol: 7 AM confirm the morning API, 12 PM advisory, main next-day decision in the afternoon, 8 PM safety update, and at any time API > 180 means close immediately.

## What the hold-out says
Waiting adds skill (see note 2) but each hour of delay costs families and hostels. For each candidate hour the backtest gives the false negatives (closures missed)
and false positives (needless closures) at every probability trigger. The dashboard picks, for each hour, the trigger with the lowest cost

`(c_miss x FN + FP) / (c_miss x closure days)  +  lateness% x (H - 3 PM)`

and then the cheapest hour. With the defaults (**a missed closure costs 8 x a needless one, each hour of lateness costs 5% of baseline**) the cheapest hour is **3 PM**
at a trigger of 0.15; an 8 PM re-check captures most of the late gain.

## Reading it
* The API does **not** always spike in the evening; it varies by episode, so the rule is trend-based, not clock-based.
* The earliest candidate (3 PM) wins as soon as waiting costs about **1% of baseline per hour or more**; later hours only win when waiting is nearly free (0.5% per hour or less), where the best hour is 5-9 PM. The gain in skill from waiting is real but small next to the cost of making families wait.
* The dashboard's *Announce time* tab recomputes this live with its two sliders.
* Because the cost function counts closure days only, it says nothing about weekends, public holidays or exam days.
